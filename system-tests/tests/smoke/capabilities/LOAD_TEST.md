# Load Testing for Keystone DONs

This document describes the load testing scenarios implemented in `workflow_don_load_test.go` and `writer_don_load_test.go`.

# Test Environment Configuration

The load tests can be run in three different environments:

1. **Local with CTFv2**
```toml
[infra]
type = "docker"
```
Runs tests locally using Docker containers, ideal for development and initial testing.

2. **CRIB Local (Kind)**
```toml
[infra]
type = "crib"

[infra.crib]
namespace = "crib-local"
folder_location = "/Users/USER_NAME/crib/deployments/cre"
provider = "kind"
```
Uses local Kubernetes cluster (Kind) for testing in an environment closer to production.

3. **CRIB AWS**
```toml
[infra]
type = "crib"

[infra.crib]
namespace = "crib-workflow_don_load_test"
folder_location = "/Users/USER_NAME/crib/deployments/cre"
provider = "aws"
```
Runs tests in AWS using EKS clusters, simulating real production conditions.

# Workflow Configuration for Load Tests

These tests use YAML-based workflows instead of compiled binaries:

```toml
[workflow_config]
workflow_name = "abcdefgasd"
should_compile_new_workflow = false

[workflow_config.compiled_config]
binary_url = "xxx"  # Required but not used
config_url = "xxx"  # Required but not used
```

Key points:
- No workflow binaries needed
- No gateway node in the configuration

# Image Configuration for Different Environments

The image configuration varies based on the deployment environment:

```toml
# For local CTFv2 or Kind (using local registry)
image = "localhost:5001/chainlink:develop"

# For AWS (using ECR)
image = "795953128386.dkr.ecr.us-west-2.amazonaws.com/chainlink:5616a0b22c00bc6dac749893beca60da2af94985-plugins"
```

- **Local/Kind**: Use local registry (`localhost:5001`)
- **AWS**: Must use ECR registry accessible to `crib-stage` environment
    - Requires proper image tag and ECR repository
    - Image must be pushed to the specified ECR repository

Remember to uncomment the appropriate image line based on your deployment target.

# Image Generation and Registry Notes

To generate Chainlink node images:
- Run integration test `Build Chainlink Image (plugins)`


⚠️ **Important**: The ECR repository is periodically purged, making the images ephemeral. You may need to rebuild and push the image if it's no longer available in ECR.



# Troubleshooting

### Error: `failed to add entry to /etc/hosts`

This error occurs when the test cannot modify `/etc/hosts` due to insufficient permissions. The fix involves:

1. Navigate to the CRE directory:
   ```bash
   cd ~/crib/deployments/cre
   ```

2. Enter the Nix development shell:
   ```bash
   nix develop
   ```
3. Run ingress-check:
    ```bash
    crib devspace ingress-check 
    ```

    If this fails try running the deployment that is failing:
    ```bash
    devspace run deploy-geth-chain
       ```
       ```bash
       devspace run deploy-custom-geth-chain
       ```
       ```bash
       devspace run deploy-jd
       ```
       ```bash
       devspace run deploy-don
       ```

**Why this works**: The shell provided by `nix develop` is interactive and can prompt for sudo password, allowing the required host entries to be added to `/etc/hosts`. The test environment's non-interactive shell cannot handle these sudo prompts.

In order for this to work the configs inside `/system-testing/test/smoke/capabilities/crib-config` should already be generated by the test. 

Alternatively you can add these paths to `/etc/hosts` manually.

### Connection Issues
If you encounter connection problems:  
Check pod health:

`kubectl get pods`

Ensure all pods show "Running" status.  
View pod logs:

`kubectl logs <POD_NAME>`
